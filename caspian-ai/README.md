# Эко-Щит Каспия — цифровой помощник инспектора ООПТ

[![CI](https://github.com/Pridurchik/kaspiy_2026/actions/workflows/ci.yml/badge.svg)](https://github.com/Pridurchik/kaspiy_2026/actions/workflows/ci.yml)

Прототип программно-аппаратного комплекса для кейса 1 КЦФ 2026 «Эко-Щит Каспия»: собирает данные
**акустических буёв, датчиков воды, спутника и AIS** в одну ленту тревог с картой, объясняет каждую
тревогу и прогнозирует нерест для превентивного патрулирования.

> **Честно о готовности.** Акустическая модель — рабочий прототип, но **не готова к полю**: её
> метрики получены на реальных, однако **воздушных** записях (ESC-50, UrbanSound8K), а потоковые
> ложные тревоги в десятки раз выше приемлемых. Полный разбор с воспроизведёнными цифрами —
> [`MODEL_AUDIT.md`](MODEL_AUDIT.md). Политика данных — [`PRIVACY.md`](PRIVACY.md), лицензия — [MIT](LICENSE).

```bash
uv venv -p 3.11 .venv && uv pip install -p .venv/bin/python -r requirements.txt
make demo            # собрать демо-ночь и открыть дашборд: http://localhost:8000
make buoys           # (в другом терминале) 3 буя шлют алерты с клипами на сервер
```

## Соответствие требованиям кейса

| Требование MVP | Что сделано | Где |
|---|---|---|
| **Дашборд инспектора** с картой ООПТ, экостатусом и алертами | веб-дашборд: карта (зоны, буи, датчики, AIS, треки, спутниковый слой), лента тревог по риску с причинами, карточка с аудио и спектрограммой, решения инспектора, экостатус зон, живые обновления | `inspector.py`, `dashboard/` |
| **Модуль ИИ-аналитики** по аудио: браконьерские лодки и выстрелы | CNN (ONNX 9 МБ) на буе + перепроверка на сервере; незнакомые звуки; пеленг лодки по 3 буям; «тёмная лодка» (сверка с AIS) | `model.py`, `detect.py`, `localize.py`, `fusion.py` |
| …или по спутнику: незаконные сбросы | шлейфы мутности Sentinel-2 (ΔNDTI), маска облаков, подтверждение датчиками воды | `satellite.py` |
| **Предиктивный модуль**: нерест по гидрологии | прогноз нереста 5 видов на 14 дней (температура воды, градусо-дни, половодье, ансамбль 50 сценариев) → окна запрета и план патрулей | `forecast.py` |
| Агрегация IoT-датчиков воды | станции T/pH/O₂/мутность/электропроводность/уровень: детектор сбросов с учётом суточного цикла, отличает сброс от сбоя датчика | `water.py` |
| Аппаратная часть | клиент буя (Raspberry Pi), схема, энергобюджет, связь, стоимость пилота | `edge.py`, [docs/hardware.md](docs/hardware.md) |
| **Прогноз миграции** осетровых (весь Каспий) | тепловая карта «где рыба будет завтра» на 7 дней по солёности, температуре, уровню и датчикам; хоуминг стада к родным рекам по воде; обучение пригодности на наблюдениях | `caspian.py`, `migration.py` |
| Предугадывание браконьеров | горячие точки на ближайшие ночи: история задержаний + прогноз миграции + берег, посёлки, луна, ветер; проверка по времени | `poaching.py` |
| **Трансграничный протокол** (Тегеранская конвенция) | черновики уведомлений соседям RU/EN по квадратам 0.5°, контрольная сумма, одобрение диспетчером | `transboundary.py` |
| Гидроакустическая сеть раннего предупреждения | тип судна по гармоникам двигателя, приближается/удаляется; «🎧 Буи в эфире» — реакция в реальном времени | `vessel.py`, `edge.py` |

**Демо-ночь 20 мая 2026** (все данные синтетические и помечены «демо»; модули принимают реальные данные):
теплоход с AIS идёт по судовому ходу → лодка без AIS заходит на нерестилище, где по прогнозу идёт нерест
сазана и осетра → с лодки стреляют (на этой сцене модель выстрел **пропускает**, см. ниже) → датчики воды ловят ночной сброс у рыбоцеха, шлейф за 2 ч доходит до
нерестилища → утренний снимок Sentinel-2 показывает шлейф 33 га и подтверждается датчиками. Кнопка
«▶ Проиграть ночь» выдаёт тревоги по одной, как они приходили.

```
 акустические буи ─┐ алерт + клип 8 с (GPS-время)       ┌─ дашборд инспектора (карта, лента, прогноз)
 (edge.py, ONNX)   ├──────────────────────────────►  inspector.py ──┤
 датчики воды ─────┤ показания каждые 10 мин  каскад, пеленг,       └─ решения инспектора -> data/feedback/
 Sentinel-2 ───────┤ шлейфы мутности          фьюжн, риск, SQLite        -> дообучение модели
 AIS ──────────────┘ суда                      прогноз нереста (гидрология)
```

Проверки: `make test` (ключевая логика, 11 тестов, ~10 с, без torch) и `make check`
(согласованность артефактов модели: классы, пороги, ONNX, OOD). Оба запускаются в CI.

## От погони к предотвращению: Каспий целиком

Вкладка **«Каспий»** на дашборде переключает карту с участка дельты на всё море.

**1. Прогноз миграции осетровых** (`migration.py`). Сетка 0.1° (~3900 морских ячеек), среда на дату:
климатическая основа + поправка по существующим датчикам (интерполяция невязок). На демо-данных датчики
снижают ошибку восстановления солёности с 0.67 до 0.10‰, температуры — с 0.18 до 0.09 °C.
- *Пригодность среды* для стадии: молодь — солёность 8–9‰ и 24–28 °C (из постановки задачи, **проверить у
  ихтиологов**), производители — 6–21 °C, низкая солёность; глубина с учётом уровня моря (падение уровня
  осушает мелководье севера).
- *Движение*: за сутки рыба уходит не дальше суточного хода (молодь ~8 км, взрослые ~25 км) в сторону
  пригодной среды, масса сохраняется. Производители **идут к родной реке по воде** (Волга 60%, Урал 25%,
  Кура 10%, Терек 5%; кратчайший путь в обход суши), поэтому видны маршруты вдоль берегов.
- *Обучение*: `fit_observations` — логистическая регрессия наличия рыбы по T, S, глубине на учётных
  съёмках. В демо (синтетические съёмки) модель восстанавливает оптимум солёности ~8.8‰, AUC 0.75 на
  отложенных неделях. С реальными траловыми данными параметры перестанут быть экспертными.
- Выход: карта на 0–7 суток, центр масс стада, **доли стада в водах каждого государства**, квадраты с
  наибольшей плотностью. Демо 20 мая: 64% производителей у Волги (квадрат D4 — наш участок), 24% у Урала.

**2. Браконьерские маршруты** (`poaching.py`). Логистическая регрессия на истории инцидентов (выгрузки
задержаний, итоги операций вроде казахстанской «Бекіре», наши тревоги): ln(плотность рыбы по прогнозу
миграции), расстояние до берега и посёлков, прошлые инциденты рядом (только до даты — без подглядывания),
тёмность ночи по фазе луны, ветер. Проверка по времени (обучение на 18 месяцах, оценка на 6): AUC 0.95,
5% площади моря с наибольшим риском покрывают 63% будущих инцидентов. **История в демо синтетическая**
(сгенерирована скрытым процессом), так что это проверка конвейера, а не реальная точность. Каждая горячая
точка объясняется: «много рыбы по прогнозу миграции; близко к берегу; рядом места выхода лодок».

**3. Трансграничный протокол** (`transboundary.py`). Рамочная конвенция по защите морской среды Каспия
(Тегеран, 2003) предусматривает сотрудничество и обмен информацией. Система собирает черновик уведомления
каждому соседу, чьих вод касается ситуация:
> В квадрате D4 (Россия) зафиксирована активность браконьеров: лодка без AIS. По модели миграции
> 24% нерестового стада осетровых находится в ваших водах; завтра наибольшая плотность — квадраты B11.
> Прогноз браконьерства на ночь: высокий риск в квадратах B11, F8. Рекомендуем усилить патрулирование…

- Машиночитаемый JSON (схема `caspian-eco-alert/0.1`) + текст на русском и английском.
- Минимизация данных: только квадраты 0.5°, без координат патрулей, персональных данных и аудио.
  Свои наблюдения попадают соседу, только если они не дальше 300 км от его вод.
- SHA-256 канонического JSON: подмена видна. **Ничего не отправляется автоматически**: черновик →
  «одобрено» диспетчером → отправка по каналу, согласованному сторонами (контакты в конфиге — заглушки).
- Принадлежность ячейки — по ближайшему побережью: это маршрутизация уведомлений, **не морская граница**.
  Контур моря схематичный (~40 точек).

**4. Гидроакустика раннего предупреждения** (`vessel.py`). По клипу тревоги: частота вспышек двигателя
по гармоникам (с защитой от субгармонических ошибок) → тип: подвесной мотор маломерной лодки (f₀ > 40 Гц),
стационарный двигатель катера, низкооборотный дизель крупного судна; направление — по тренду уровня и
доплеровскому сдвигу. Это эвристика, а не обученный классификатор: для классов «рыба / лодка / шум волн»
нужны размеченные подводные записи (ShipsEar, DeepShip, свои гидрофоны), пайплайн их принимает (`folder:`).
Кнопка **«🎧 Буи в эфире»** запускает три буя в реальном времени на записанной ночи: тревоги появляются
на дашборде по мере звука.

# Акустический ИИ-модуль

По звуку с акустического буя определяет **мотор лодки**, **выстрел**, **бензопилу** (возможная рубка)
и **авиацию**, помечает **незнакомые звуки** (OOD, «честное не знаю») и выдаёт события и алерты.

| | |
|---|---|
| Модель | CNN 1.18 млн параметров, **ONNX 9 МБ** (звук → вероятности + эмбеддинг одним файлом) |
| Скорость (1 поток CPU) | 4 мс на окно 2 с → **~1% CPU** в реальном времени; час записи — 18 с на сервере |
| Данные | ESC-50 + UrbanSound8K (реальные выстрелы) + синтетика **только в train**; val/test — только реальные записи |

**Качество на реальных записях** (тест, потоковая детекция: окна, пороги, N окон подряд; сервер):

| | Было (до переобучения) | Стало |
|---|---|---|
| Выстрел: доля пойманных, SNR 10 / 0 дБ | 17% / 19% | **44% / 32%** (буй с порогом 0.8: 59% / 54%) |
| Ложных «выстрелов» в час: незнакомые звуки / реальный фон | 18.7 / 13.4 | **4.0 / 4.5** |
| Мотор: доля пойманных, SNR 10 / 0 дБ | 22% / 10% | 27% / 20% |
| OOD «не знаю», AUROC (только реальные клипы) | — | 0.65 |
| Ложных `unknown_sound` в час (незнакомые звуки / реальный фон) | 84 / 67 | **2 / 0** |

Порог выстрела выбран по **ложным тревогам в час**, а не по F-мере на клипах: при 0.5 модель ловит 97%
выстрелов, но даёт ~100–125 ложных в час (хлопки, стук, звон); при 0.9 — 2–4 в час. Прежние цифры
README (precision 1.00, AUROC 0.81) держались на синтетике в тесте — теперь синтетика только в обучении.
Честно о слабых местах: мотор в потоке ловится плохо (записи моторов в датасетах — с воздуха и с берега,
а не с гидрофона), выстрел издалека на фоне мотора модель путает с петардой (в демо-сцене вероятность
выстрела 0.4–0.6 при пороге 0.9 — тревоги нет). Попытка добавить трудные негативы из ESC-50 ухудшила
ложные тревоги на отложенных категориях (247/ч против 104/ч) — выключено. Главное лекарство — свои записи:
гидрофоны на месте и «ложные тревоги» инспекторов (они уже собираются в `data/feedback/`).

**Архитектура — каскад:** буй = «параноидальная растяжка» (заниженные пороги `edge_thresholds`,
задача — не пропустить; алерт стоит 1 КБ трафика), сервер = «эксперт» (перепроверяет каждый
присланный клип строгими порогами + фьюжн с AIS/зонами нереста). Так же устроены голосовые
ассистенты: крошечная модель на устройстве, умная — в облаке.

```
источники аудио ─► prepare ─► train ─► evaluate ─► export (ONNX)
                                                     │
                     ┌───────────────────────────────┼───────────────────────────┐
                     ▼                               ▼                           ▼
             cli detect (файл)            serve.py (FastAPI)          edge.py (буй / Raspberry Pi)
                     └──────────── события ─► алерты JSON ─► дашборд / фьюжн ◄─────┘
```

## Быстрый старт

```bash
uv venv -p 3.11 .venv && uv pip install -p .venv/bin/python -r requirements.txt
make smoke        # синтетика -> обучение -> метрики -> ONNX -> детекция на демо-сцене
```

`make smoke` нужен только чтобы проверить, что весь пайплайн работает. Синтетические звуки
**не годятся** для боевой модели.

**`make smoke` изолирован** (`configs/audio_smoke.yaml`): пишет в `data/smoke/` и `runs/smoke/`
и **не перезаписывает** боевые `data/manifest.csv` и `runs/audio/*`. Раньше запуск smoke затирал
готовую модель и манифест — теперь это невозможно.

## Данные

| Источник | Что даёт | Как получить |
|---|---|---|
| **ESC-50** | `engine` → мотор; волны, дождь, ветер, птицы → фон; вертолёт, бензопила, фейерверк → трудные негативы | `cli download esc50` (~600 МБ) |
| **UrbanSound8K** | `gun_shot` → **выстрел** (≈370 клипов), `engine_idling` → мотор | zenodo.org/record/1203745, распаковать в `data/raw/UrbanSound8K` |
| **ShipsEar** | подводные записи моторных лодок | по запросу у авторов, затем `folder:PATH=boat_motor` |
| **DeepShip** | подводные шумы крупных судов (как фон или отдельный класс) | GitHub irfankamboh/DeepShip |
| **Свои записи** | гидрофон или микрофон на месте, самое ценное | `folder:PATH` (подпапки `background/`, `boat_motor/`, `gunshot/`) |

В ESC-50 выстрелов нет, поэтому для реальной модели нужен UrbanSound8K или свои записи выстрелов.
Сплит train/val/test **групповой**: нарезки одной записи не попадают в разные выборки, иначе метрики завышены.

## Что внутри

- **Признаки:** log-mel 64 полосы, 20–8000 Гц, n_fft = 1024 (разрешение ~16 Гц, чтобы различать гармоники мотора 20–90 Гц).
  Признаки считаются *внутри модели* (STFT через conv1d), поэтому ONNX — это один файл «сырой звук → вероятности».
- **Модель:** CNN из 4 блоков (≈1.2 млн параметров), mean+max-пулинг по времени (max ловит короткий выстрел).
- **Аугментации под поле:** наложение события на фон с SNR от −5 до +20 дБ (имитация расстояния до буя), случайное усиление,
  инверсия полярности, SpecAugment. Обрезка событий «по энергии», чтобы выстрел гарантированно попадал в окно.
- **Дисбаланс классов:** взвешенная кросс-энтропия, label smoothing; early stopping по macro-F1.
- **Детекция в потоке:** окно 2 с, шаг 0.5 с. Алерт срабатывает, если вероятность выше порога N окон подряд
  (мотор: 3 окна, выстрел: 1 окно). Пороги задаются в `configs/audio.yaml`; `cli tune` подбирает их на валидации.
- **Классы-буферы:** авиация и бензопила выделены из фона — раньше вертолёт/пила давали ложные тревоги
  по мотору, теперь это отдельные (и полезные) алерты, а мотор/выстрел на тесте без ложных срабатываний.
- **«Честное не знаю» (OOD):** оценка = расстояние эмбеддинга до центров классов + энтропия softmax,
  ранговая калибровка по валидации (AUROC ≈ 0.65 на 27 незнакомых категориях ESC-50; см. `MODEL_AUDIT.md`). Незнакомый звук
  даёт алерт `unknown_sound` «требуется проверка» вместо уверенной ошибки. Работает и на буе: ONNX отдаёт
  эмбеддинг вторым выходом, рядом с моделью лежит `ood.npz`.
  **Операционная точка важнее AUROC:** порог OOD задаётся в конфиге (`inference.ood.threshold`, сейчас 0.95,
  `min_consecutive: 3`) и переопределяет 0.95-квантиль из `ood.npz`. Так `unknown_sound` снижен с ~84 до **~2 ложных/ч**.

## API для дашборда

```bash
make serve
curl -F file=@data/scene.wav -F sensor_id=buoy-07 -F lat=45.75 -F lon=48.40 localhost:8000/v1/acoustic/detect
```
Ответ содержит `events`, `alerts` (готовые карточки для ленты) и `timeline` (вероятности по окнам для графика).
Можно приложить выгрузку AIS (`-F ais=@ais.csv`) и время записи (`-F recorded_at=…`): каждый алерт получает
блок `fusion` с баллом риска и причинами (см. ниже).

| Эндпоинт | Что делает |
|---|---|
| `POST /v1/acoustic/detect` | один буй: события, алерты, таймлайн (+ фьюжн: зоны, ночь, AIS рядом) |
| `POST /v1/acoustic/array` | сеть буёв: WAV каждого буя (`files`), `buoys` (JSON с координатами), `recorded_at`, опционально `ais` → алерты с точкой, треком, опознанием |
| `POST /v1/fusion/assess` | алерты из любого источника + AIS (JSON) → опознание и балл риска |

Формат алерта:
```json
{"id": "…", "type": "acoustic", "category": "gunshot", "title": "Выстрел", "severity": "high",
 "confidence": 0.97, "sensor_id": "buoy-07", "location": {"lat": 45.75, "lon": 48.4},
 "start_ts": "…", "end_ts": "…", "model_version": "audio-cnn-0.1", "status": "new"}
```

## Сеть буёв: пеленг и «тёмная лодка»

```bash
make array-demo     # симуляция 3 буёв -> пеленг -> фьюжн -> runs/array_demo/map.html
```

Инспектору важно не «шумит ли мотор», а **кто это, где он и надо ли ехать**. Два модуля поверх детектора:

**1. Пеленг (`localize.py`).** Буи пишут звук с общим временем по GPS. Звук приходит на ближний буй
раньше, на дальний позже: разность времён прихода (TDOA) для пары буёв задаёт гиперболу, пересечение
гипербол — точка источника. Серия точек → трек (фильтр Калмана + сглаживание) → **скорость, курс и время
подхода к запретной зоне**.
- Задержки считаются GCC-PHAT в полосе кавитации винта (широкополосный шум даёт острый пик).
- **Компенсация Доплера.** У идущей лодки разность задержек «плывёт» на миллисекунды за окно: без
  компенсации пик расплывается и выигрывают ложные пики гармоник (ошибка в периоды вращения, 15–60 м).
  Перебираем скорость изменения задержки и растягиваем сигнал. На симуляции доля верных задержек
  (окно 0.5 с) выросла с ~7% до 100%.
- Скорость звука по классам: мотор слышит гидрофон (вода, 1480 м/с), выстрел и пилу — микрофон (воздух, 343 м/с).
- Радиус неопределённости честный: учитывает ошибку скорости звука (~1%), которая не усредняется,
  и геометрию (вне треугольника буёв дальность определяется хуже, радиус растёт).

**2. Фьюжн (`fusion.py`).** Каждому алерту — **балл риска 0–100 с причинами**:

| Фактор | Баллы (конфиг `fusion.risk`) |
|---|---|
| выстрел / пила / мотор / незнакомый звук | +40 / +35 / +20 / +10 |
| **«тёмная лодка»**: мотор есть, судна с AIS в точке пеленга нет | +25 |
| опознано по AIS / свой патрульный катер | −15 / только «инфо» |
| в зоне с действующим запретом (нерестилище в сезон, заповедное ядро) | +25…+30 |
| на судовом ходу | −10 |
| идёт к запретной зоне, подход < 15 мин | +10 |
| ночь | +10 |

Итог умножается на уверенность детектора; пороги приоритета: critical ≥ 75, high ≥ 55, medium ≥ 35.
Зоны — GeoJSON (`configs/zones_demo.geojson`, **условные демо-полигоны**: заменить на официальные
границы и сроки запрета), AIS — CSV `mmsi, ts, lat, lon, name` (формат обычных выгрузок).

**Почему нужна именно сеть.** Один буй слышит всё в радиусе ~2 км и не может сказать, шумит ли
теплоход с AIS на судовом ходу или лодка без AIS рядом, поэтому честно пишет «рядом судно с AIS, нужен
пеленг» (низкий приоритет). Сеть находит точку: в демо одиночный буй даёт лодке ~28 баллов (low),
сеть — 80 (critical: лодка без AIS на нерестилище ночью в период запрета).

**Демо-сцена** (ночь 20 мая, нерестовый запрет; 150 с): теплоход с AIS идёт по судовому ходу, лодка
без AIS заходит на нерестилище, с лодки стреляют (в `make array-demo` — реальная запись выстрела из тестовой части
UrbanSound8K). В симуляцию заложены полевые эффекты: эхо от берегов,
ошибка GPS буёв ±2 м, рассинхронизация часов 50 мкс, скорость звука на 0.8% ниже заложенной.

Результаты на 5 случайных прогонах симуляции (разный шум, эхо, ошибки GPS и часов):

| Источник | Ошибка трека (медиана по прогонам) | Опознание | Приоритет |
|---|---|---|---|
| Лодка без AIS, внутри треугольника буёв | **3–4 м** | «тёмная» 5/5 | critical 78–80 |
| Выстрел с лодки (одна засечка) | **2–6 м** (если распознан; замер с прежней моделью и синтетическим выстрелом) | — | high/critical 61–75 |
| Теплоход с AIS, ~0.8–2 км **вне** треугольника | 120–180 м | AIS, верный MMSI 5/5 | low 5 |

Вне сети буёв направление определяется хорошо, а дальность — плохо (гиперболы почти параллельны).
Для опознания по AIS этого хватает, потому что радиус неопределённости честно растёт. Буи стоит
ставить так, чтобы охраняемая зона была внутри сети.

Честные ограничения: это **симуляция** (прямой луч + 2 эха, без мелководной многолучёвости, ветра и
течения). На реальной воде ошибка будет больше: нужны полевые записи 2–3 гидрофонов с GPS-синхронизацией.
Маломерные суда не обязаны иметь AIS: «тёмная лодка» = «не опознана», а не «нарушитель»; в запретной зоне
это повод для приоритетного выезда. Для выстрела нужен микрофон над водой (в воде выстрел почти не слышен).

# Датчики воды (`water.py`)

Станции присылают температуру, pH, растворённый кислород, мутность, электропроводность и уровень
(`POST /api/water`). У воды суточный цикл (днём фотосинтез поднимает O₂ и pH), поэтому каждое
значение сравнивается с **тем же часом суток** за прошлые дни (медиана и MAD).
- **Сброс:** согласованное отклонение ≥ 2 параметров дольше 30 минут. Если потом то же приходит на
  станцию ниже по течению, это шлейф, и алерт показывает, за сколько часов он дошёл.
- **Сбой датчика:** один параметр, одиночный выброс или «залипание» на одном значении.
  Такой алерт информационный, это повод для обслуживания, а не тревога.
- Нормативы: O₂ ≥ 6 мг/л, pH 6.5–8.5 (рыбохозяйственные).

# Спутник (`satellite.py`)

Sentinel-2 L2A: водная маска по NDWI, мутность по NDTI = (B4 − B3)/(B4 + B3). Сброс = рост NDTI
относительно предыдущего снимка на связном участке воды ≥ 1 га. Облака и их кромка исключаются (иначе
дымка даёт ложные шлейфы); ΔNDTI сглаживается по окну 5×5. Шлейф рядом со станцией, где в последние
24 ч был сброс, получает «подтверждено датчиками» (+25 к риску). В демо — синтетическая пара снимков;
для реальных: Copernicus Data Space → каналы B03/B04/B08 → npz (формат в docstring модуля).

# Прогноз нереста (`forecast.py`)

```bash
PYTHONPATH=src .venv/bin/python -m caspian_audio.cli forecast --hydro temp_discharge.csv --plan popusk.csv
```
Вход: суточная температура воды и расход Волги (Росгидромет), график весеннего попуска Волжской ГЭС
(публикуется заранее). Для 5 видов (вобла, судак, лещ, русский осётр, сазан):
`интенсивность = пригодность температуры × созревание (градусо-дни с 1 марта) × половодье × остаток запаса`.
Неопределённость — ансамбль 50 сценариев температуры (аномалия года затухает к норме, разброс растёт).
- **Окна запрета по прогнозу:** тревога на нерестилище получает «идёт нерест — сазан, 100%»
  вместо фиксированных дат.
- **План патрулирования:** вероятность нереста × число браконьерских тревог в зоне → где и когда дежурить.
- Параметры видов ориентировочные: их нужно откалибровать с ихтиологами (КаспНИРХ) на учётных данных.

# Платформа и дашборд (`inspector.py`, `dashboard/`)

`make demo` → http://localhost:8000. Один сервер: API всех источников, SQLite, Server-Sent Events.

| Эндпоинт | Что делает |
|---|---|
| `GET /` | дашборд инспектора |
| `POST /api/alerts` | алерт с буя + клип (base64) + GPS-время клипа: перепроверка строгими порогами; при ≥3 буях — пеленг по клипам |
| `POST /api/water` | показания станции → детектор сбросов → новые тревоги |
| `GET /api/alerts`, `GET /api/alerts/{id}` | лента по приоритету и риску, карточка тревоги |
| `GET /api/alerts/{id}/audio`, `…/spectrogram.png` | аудио-доказательство и спектрограмма |
| `POST /api/alerts/{id}/status` | решение инспектора: `in_progress`, `confirmed`, `false_alarm`, `closed`; клип уходит в `data/feedback/<класс>/` |
| `GET /api/overview`, `GET /api/forecast`, `GET /api/water/{station}` | слои карты, экостатус, прогноз и план патрулей, ряды датчиков |
| `GET /api/stream` | живые события (новая тревога, смена статуса, вода) |
| `POST /api/demo/replay` | «проиграть ночь» для показа |

**Петля обучения:** «Подтвердить» сохраняет клип в его класс, «Ложная тревога» — в фон как трудный
негатив. Дообучение: `prepare --sources … folder:data/feedback`.

**Буй → сервер:** `edge.py --post` шлёт алерт с 8-секундным клипом и GPS-временем его начала.
Повтор того же класса — не чаще раза в 30 с. Если событие прислали ≥ 3 буя, сервер строит общий
таймлайн и считает пеленг (`make buoys`: на демо-сцене три буя дали точку мотора ±24 м).
Ограничение: пеленг считается, только если событие распознали ≥ 3 буя. Следующий шаг — запрос клипа
у соседних буёв по алерту одного (кольцевой буфер 60 с на буе).

## Безопасность и ограничения

Перед любым реальным развёртыванием (детали — [`MODEL_AUDIT.md`](MODEL_AUDIT.md), [`PRIVACY.md`](PRIVACY.md)):

- **Не включайте параноидальный профиль буя как есть.** `edge_thresholds` дают ~90 ложных «пил»/ч и
  ~23 «выстрела»/ч — буй годится только как датчик-«растяжка», а каждый алерт обязан проходить
  серверную перепроверку строгими порогами и решение человека. Пороги буя нужно пересчитать под
  приемлемый бюджет ложных тревог.
- **`unknown_sound` теперь ~2/ч** (было 67–84/ч): порог OOD вынесен в конфиг и поднят до 0.95 при 3 окнах
  подряд (`inference.ood`). Остаточный риск — OOD не отличает безобидное «незнакомое» от опасного;
  лечится полевыми «ложными тревогами» инспекторов (`data/feedback/`) и дообучением.
- **Нет аутентификации** у дашборда и API — только доверенная сеть. Перед публикацией: HTTPS,
  вход инспектора, разграничение ролей.
- **Зоны и контакты сторон — демо-заглушки** (`zones_demo.geojson`, конфиг трансграничного протокола):
  заменить на официальные границы, сроки запрета и координационные центры.
- Трансграничные уведомления **не отправляются автоматически** — только черновик → одобрение диспетчера.

## Как улучшить модель

1. **Свои записи с места** (даже 30 минут фона дельты Волги) резко снижают число ложных тревог.
2. **Предобученный бэкбон** (PANNs CNN14, BEATs, AST на AudioSet) с дообучением только головы — это +10–20% F1 на малых данных.
3. **Подбор порогов** по кривой precision/recall на валидации: инспектору важнее мало ложных тревог.
4. **Hard negative mining:** уже собирается автоматически — «ложная тревога» на дашборде кладёт клип в `data/feedback/background/`.
5. **Подводные записи:** ESC-50 и UrbanSound8K записаны в воздухе, а буй слушает гидрофоном — нужны ShipsEar/DeepShip и свои записи.
