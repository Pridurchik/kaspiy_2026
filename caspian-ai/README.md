# Caspian OOPT — акустический ИИ-модуль

Пайплайн для модуля ИИ-аналитики «цифрового помощника инспектора ООПТ»: по звуку с акустического буя
определяет **мотор лодки**, **выстрел**, **бензопилу** (возможная рубка) и **авиацию**, помечает
**незнакомые звуки** (OOD, «честное не знаю») и выдаёт события и алерты для дашборда.

**Ключевые цифры** (замерено, тестовая выборка):

| | |
|---|---|
| Модель | CNN 1.18 млн параметров, **ONNX 9 МБ** (звук → вероятности + эмбеддинг одним файлом) |
| Алерты «мотор» и «выстрел» | precision 1.00, **0 ложных тревог** (recall 0.97 / 1.00) |
| OOD «не знаю» | AUROC 0.81 на 30 незнакомых категориях звуков |
| Скорость (1 поток CPU) | 4 мс на окно 2 с → **~1% CPU** в реальном времени; час записи — 18 с на сервере |
| Обучение с нуля | ~4 минуты (Apple M4 / любой GPU / CPU) |

**Архитектура — каскад:** буй = «параноидальная растяжка» (заниженные пороги `edge_thresholds`,
задача — не пропустить; алерт стоит 1 КБ трафика), сервер = «эксперт» (перепроверяет каждый
присланный клип строгими порогами + фьюжн с AIS/зонами нереста). Так же устроены голосовые
ассистенты: крошечная модель на устройстве, умная — в облаке.

```
источники аудио ─► prepare ─► train ─► evaluate ─► export (ONNX)
                                                     │
                     ┌───────────────────────────────┼───────────────────────────┐
                     ▼                               ▼                           ▼
             cli detect (файл)            serve.py (FastAPI)          edge.py (буй / Raspberry Pi)
                     └──────────── события ─► алерты JSON ─► дашборд / фьюжн ◄─────┘
```

## Быстрый старт

```bash
uv venv -p 3.11 .venv && uv pip install -p .venv/bin/python -r requirements.txt
make smoke        # синтетика -> обучение -> метрики -> ONNX -> детекция на демо-сцене
```

`make smoke` нужен только чтобы проверить, что весь пайплайн работает. Синтетические звуки
**не годятся** для боевой модели.

## Шаги по отдельности

```bash
export PYTHONPATH=src; PY=.venv/bin/python
$PY -m caspian_audio.cli synth --per-class 200
$PY -m caspian_audio.cli download esc50
$PY -m caspian_audio.cli prepare --sources synthetic esc50 urbansound8k \
      folder:/data/shipsear/motorboat=boat_motor folder:/data/our_hydrophone   # подпапки = классы
$PY -m caspian_audio.cli train
$PY -m caspian_audio.cli evaluate          # отчёт по классам, матрица ошибок, precision/recall алертов
$PY -m caspian_audio.cli tune              # подбор порогов алертов на валидации (F0.5: приоритет precision)
$PY -m caspian_audio.cli export            # runs/audio/model.onnx (logits+embedding) + model.json
$PY -m caspian_audio.cli ood               # детектор незнакомых звуков -> runs/audio/ood.npz + AUROC
$PY -m caspian_audio.cli scene             # 60-секундная демо-сцена с разметкой
$PY -m caspian_audio.cli detect data/scene.wav --out runs/audio/scene_detect.json
```

## Данные

| Источник | Что даёт | Как получить |
|---|---|---|
| **ESC-50** | `engine` → мотор; волны, дождь, ветер, птицы → фон; вертолёт, бензопила, фейерверк → трудные негативы | `cli download esc50` (~600 МБ) |
| **UrbanSound8K** | `gun_shot` → **выстрел** (≈370 клипов), `engine_idling` → мотор | zenodo.org/record/1203745, распаковать в `data/raw/UrbanSound8K` |
| **ShipsEar** | подводные записи моторных лодок | по запросу у авторов, затем `folder:PATH=boat_motor` |
| **DeepShip** | подводные шумы крупных судов (как фон или отдельный класс) | GitHub irfankamboh/DeepShip |
| **Свои записи** | гидрофон или микрофон на месте, самое ценное | `folder:PATH` (подпапки `background/`, `boat_motor/`, `gunshot/`) |

В ESC-50 выстрелов нет, поэтому для реальной модели нужен UrbanSound8K или свои записи выстрелов.
Сплит train/val/test **групповой**: нарезки одной записи не попадают в разные выборки, иначе метрики завышены.

## Что внутри

- **Признаки:** log-mel 64 полосы, 20–8000 Гц, n_fft = 1024 (разрешение ~16 Гц, чтобы различать гармоники мотора 20–90 Гц).
  Признаки считаются *внутри модели* (STFT через conv1d), поэтому ONNX — это один файл «сырой звук → вероятности».
- **Модель:** CNN из 4 блоков (≈1.2 млн параметров), mean+max-пулинг по времени (max ловит короткий выстрел).
- **Аугментации под поле:** наложение события на фон с SNR от −5 до +20 дБ (имитация расстояния до буя), случайное усиление,
  инверсия полярности, SpecAugment. Обрезка событий «по энергии», чтобы выстрел гарантированно попадал в окно.
- **Дисбаланс классов:** взвешенная кросс-энтропия, label smoothing; early stopping по macro-F1.
- **Детекция в потоке:** окно 2 с, шаг 0.5 с. Алерт срабатывает, если вероятность выше порога N окон подряд
  (мотор: 3 окна, выстрел: 1 окно). Пороги задаются в `configs/audio.yaml`; `cli tune` подбирает их на валидации.
- **Классы-буферы:** авиация и бензопила выделены из фона — раньше вертолёт/пила давали ложные тревоги
  по мотору, теперь это отдельные (и полезные) алерты, а мотор/выстрел на тесте без ложных срабатываний.
- **«Честное не знаю» (OOD):** оценка = расстояние эмбеддинга до центров классов + энтропия softmax,
  ранговая калибровка по валидации (AUROC ≈ 0.81 на 30 незнакомых категориях ESC-50). Незнакомый звук
  даёт алерт `unknown_sound` «требуется проверка» вместо уверенной ошибки. Работает и на буе: ONNX отдаёт
  эмбеддинг вторым выходом, рядом с моделью лежит `ood.npz`.

## API для дашборда

```bash
make serve
curl -F file=@data/scene.wav -F sensor_id=buoy-07 -F lat=45.75 -F lon=48.40 localhost:8000/v1/acoustic/detect
```
Ответ содержит `events`, `alerts` (готовые карточки для ленты) и `timeline` (вероятности по окнам для графика).

Формат алерта:
```json
{"id": "…", "type": "acoustic", "category": "gunshot", "title": "Выстрел", "severity": "high",
 "confidence": 0.97, "sensor_id": "buoy-07", "location": {"lat": 45.75, "lon": 48.4},
 "start_ts": "…", "end_ts": "…", "model_version": "audio-cnn-0.1", "status": "new"}
```

## Буй (edge)

```bash
make edge-demo                                                          # файл как живой поток
PYTHONPATH=src .venv/bin/python -m caspian_audio.edge --mic --post http://localhost:8080/api/alerts
```
На устройстве нужны только `numpy soundfile pyyaml onnxruntime` (+ `sounddevice` для микрофона).
При алерте сохраняется 8-секундный аудиоклип-доказательство.

## Структура проекта

```
configs/audio.yaml          один конфиг на всё: классы, признаки, аугментации, пороги алертов
src/caspian_audio/
  synth.py                  синтетические звуки (моторы, выстрелы, фон дельты) для smoke-теста
  prepare.py                сбор датасета: ESC-50/UrbanSound8K/свои папки -> manifest.csv
  dataset.py                PyTorch Dataset, аугментации под поле (SNR-микс, SpecAugment)
  model.py                  CNN со спектрограммой ВНУТРИ графа (на буе не нужна предобработка)
  train.py                  обучение, оценка, автоподбор порогов (tune)
  ood.py                    детектор незнакомых звуков (расстояние до центров + энтропия)
  export.py                 экспорт в ONNX (logits + embedding) со сверкой с torch
  detect.py                 потоковая детекция: окна -> события -> алерты
  serve.py                  FastAPI для дашборда: POST /v1/acoustic/detect
  edge.py                   клиент буя: микрофон/файл -> алерты + аудио-доказательства
runs/audio/                 артефакты: best.pt, model.onnx, ood.npz, метрики
```

## Как улучшить модель

1. **Свои записи с места** (даже 30 минут фона дельты Волги) резко снижают число ложных тревог.
2. **Предобученный бэкбон** (PANNs CNN14, BEATs, AST на AudioSet) с дообучением только головы — это +10–20% F1 на малых данных.
3. **Подбор порогов** по кривой precision/recall на валидации: инспектору важнее мало ложных тревог.
4. **Hard negative mining:** ложные срабатывания, отмеченные инспектором («ложная тревога»), добавляются в фон и модель переобучается.
5. **Направление на источник:** 2+ гидрофона дают TDOA и пеленг на лодку для карты.
